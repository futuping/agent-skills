# 仅在适用的产品情境加载

这些是01/02/05/08/10/14的条件补充，不新增阶段、强制表单或第二份状态台账。

## 需要商业验证时

代码完成、实际使用、愿意付款、持续使用与能够获利是不同命题。先选当前最危险假设：需求、触达、付费、可实现性、数据可用性或交付经济性。只有技术可实现性是主风险时才优先写技术原型。

访谈追问最近一次真实事件、当前替代方法、频率、损失和预算负责人；礼貌评价与候补名单不证明购买。按问题选择脱敏样例、手工服务、可操作原型或明确范围与价格的试点。拟写报价不等于已报价，意向不等于付款；样本数量和阈值是待论证的项目设定，不存在通用的“几次访谈/几单即证明PMF”。外部接触、收款、投放等仍遵守已有授权。

复用工作记录的一小段实验记录即可：待决问题 → 假设及最强替代解释 → 能改变决定的最小行动 → 预定成功/失败/不确定判据 → 预算、期限和停止条件 → 完整样本与拒绝/失败分母 → 实际结果与下一决定。不要另外复制一套阶段记录。

留存按自然使用周期观察同批用户，低频工具不套日活指标。记录人工介入、返工和支持时间，勿把隐藏人工交付称为自动化。单位经济性必须使用同一窗口、币种和任务口径：

```text
每成功任务变动成本 = 窗口内全部变动成本 / 成功交付数
同窗口可贡献金额 = 同口径净收入 - 变动成本总额
```

变动成本包含成功与失败/重试的模型、工具、基础设施、支付费用及人工交付/支持；固定成本与机会成本另列且避免重复。退款已扣净收入时不再重复计成本。零成功时单位成本未定义；未知费用保留未知，不填零。语言不能确定经营地区；实际涉及支付、税务、平台与数据规则时，先确认经营主体/目标市场并核对当时的官方要求。

## 交付的软件本身使用LLM/agent时

将模型标识与可见版本、系统提示词、检索语料/索引、工具契约、数据处理和评测集作为可追溯配置；只记录实际可见版本，不杜撰供应商内部版本。关联具体制品/提交与可用回退配置，不把文案变流畅当升级成功。

在变更前冻结代表性输入、独立预期与发布判据，覆盖正常、边界、正确拒绝、注入、工具失败/超时和模型退化。按风险验证结构输出与业务不变量、权限、人工确认/拒绝、降级和恢复；不能以一次模型自评替代系统后置条件。

比较实际任务成功、关键错误、延迟、每成功任务总成本与人工介入；失败和重试也计成本。先在隔离环境或受控小流量取得真实结果，再按原授权发布；没有API预算或部署授权时只准备方案。提示词/模型/索引更新也要走受影响的验证与发布路径。
