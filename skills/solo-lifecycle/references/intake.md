# 00 项目／任务接入、上下文准备与agent执行策略校准

阶段00于2026-10-28随1.1.0新增，1.1.1于2026-10-29修正未决路线、能力证据适用范围与复盘规则；不是任何标准的固定阶段。目标是“足以开始正确的下一步”，不是先解决所有未知。首次接入、任务/现场/能力/授权实质改变、会话恢复时触发；连续有效的上下文只做增量核对。尚无项目也可完成接入；无关翻译或概念问答不触发。

## 与相邻阶段的边界

00登记事实、缺口、能力与执行策略，选择路线。01才验证用户问题/价值；02才判断可行性/投入；03才形成需求与验收；06才实际建立、加载并验证工程环境和管线。00能记录已有这些阶段的有效证据，但不能替代它们。检查环境文件存在不等于环境可运行；工具列在配置中不等于已调用成功。

## 可裁剪的七步

1. **任务与现场**：识别无项目探索、新项目、现有项目接入、功能变更、缺陷、运行事件、维护、效果评估或退役。提取目标、非目标、限制、实际对象和已核状态。分别标事实/假设/偏好/决定/待验证；“想做产品”是意向，不是价值证据。没有仓库就如实记没有，不创建仓库来填表。
2. **相关上下文**：先读适用指令、现有工作记录，再读当前决定需要的说明、研究、需求/设计、代码、锁/CI、历史决定与验证。只访问授权相关位置，不扫无关私有目录，不全量加载。索引至少有来源/位置、有效版本或未知、权威性、已读范围、复用范围、冲突或过期风险。用户当前请求也可成为唯一初始来源。能查到的先查，不重复访谈。
3. **能力核对**：记录实际宿主/模型（无法核实则未知）、工具/skills/plugins、读写/终端/浏览器/测试/外部服务的相关能力。四态为“已可用且有依据”“已配置但未验证”“计划使用”“当前不可用”。保留依据及作用范围：工具声明支持不证明对当前账户有写权限；旧成功不证明本次成功。能力已验证须有匹配当前验证目标的实际依据；跨快照复用另附当前目标的实际影响审查，不只改证据标签。机器字段见`references/records.md`。未配置且可用性未知用“计划使用”，注明未知，不能假称不可用或已安装。无用户机器访问时只交付核查步骤。
4. **最小执行组合**：默认一个主agent、相关上下文索引、现有记录、宿主已有工具和按风险选择的外部验证器；不默认安装任何第三方项目。每项增强注明解决的问题、启用触发、成本/依赖和失效替代。旧库复杂才加RPI研究；需求明确才写小规格；行为可判才加TDD；重复LLM任务才考虑评测；需要独立验证才加其他代理。只选一个主工作流，不叠加多个完整框架。
5. **可靠性措施**：为决定路线的关键事实选版本匹配的来源；核对前提、冲突和反例；区分检索事实/推断/建议。指定独立于生成结果的预期或后置条件。知识缺口→定向查证，工具状态未知→查询状态而非盲重试，关键推理冲突→判别实验。细则按需读`references/reliability.md`。自评/代理赞同/回答变长不是证据；新策略有显著成本才做同任务小样本比较，不能声称未做的试验有效。不要求每个任务先做完整评测。
6. **边界与预算**：继承已有授权、预算与项目规则；人决定目标/不可逆取舍/新增权限，agent自主完成已授权常规工作。只对具体缺失授权提出请求，先准备可审查材料，不重复审批。安装、付费、上传、部署、删除、全局配置均不会因00自动获权。复用Nix与Home Manager单一来源；环境实际动作转06并按需读`references/environment.md`，不复制全局政策。
7. **下一步**：能够判定路线时，选最早受影响阶段和一个具体动作，写明输入、能力、授权依据、验证方式及缺口。核心方向尚未明确时，保留路线未知、未决原因和具体澄清动作，不为了填表猜阶段或标通过；机器记录的未决条件见`references/records.md`。只阻塞受影响分支；例如不能运行测试，不阻塞已授权的需求或代码只读分析。路线已有依据但下一动作仍受阻时，可完成00的“缺口已明确”结论，但不能说下一动作已可执行；优先给出不受影响的替代动作。

## 按现场裁剪

| 情境 | 00的最小核对 | 后续路线 |
|---|---|---|
| 没有项目/仓库 | 当前请求、意向与假设、可用信息渠道、禁止外部动作、下一探索问题 | 01；不先初始化06 |
| 已有项目首次接入 | 指令和有效记录、相关资产、真实版本/差异、能力与证据有效性 | 缺口所在阶段；不把01—15重走一遍 |
| 有有效工作记录 | 仅比较本次目标、对象、版本、环境、权限、未结束工具与证据变化 | 没变化就接续；变化只撤销受影响结论 |
| 小型修改 | 目标/局部影响、现有环境和授权、相关检查 | 07/受影响08；一个短段落足够 |
| 紧急事故 | 影响对象、真实状态、已有止损授权、可信runbook与副作用状态 | 紧接12；00与取证合并，不先填完整表 |
| 维护/评估/退役 | 实际触发、当前责任/依赖、已有决定、受影响证据 | 13/14/15；持续活动仍需事件/真实调度 |

## 最小产物与完成判定

扩展现有issue或工作记录的00区；只在跨会话确有需要时创建记录。记录任务类型/目标/非目标、对象与已核状态、上下文及复用、关键未知及影响、能力四态与组合、验证依据及可靠性措施、授权/预算/停止边界、路线与下一行动。无关字段合并或注明不适用，不为每项新建文档。

00通过需要：事实/假设/未知可分；路线有依据；下一步输入/能力/授权已满足或缺口明确；已有成果适当复用；接入观察能追到实际请求、文件或工具结果，计划没有写成事实。至少一个适用接入判准且全部适用判准通过才构成完整00结论；部分子条件可保留通过，但不代表路线已确定。仅接入范围的通过不要求产品已经有代码、commit或运行环境。

状态使用共同六态。允许“00通过：准备足以进入01探索；终端与测试能力未验证”。“已列核查计划”只能证明计划存在，不能证明配置完成。后续01/02/03/06/08/09/11等仍分别判断。00未决事项不足以支持任何安全下一步时标阻塞；但不阻塞无关且已授权工作。

## 记录与恢复

优先使用`assets/work-record.md`；需要机器检查才读`references/records.md`。00接入证据为对实际请求/上下文的观察或真实决定，判准kind=intake、stage=00、target_type=context；不是产品execution。无仓库/环境可为null，但给出原因和上下文snapshot_id。后续产品判准仍绑定真实软件对象/版本/环境。不得拿接入观察替代测试或用户接受。

恢复顺序：权威指令→已有00/任务记录→真实变化与未结束工具→证据有效性→更新必要字段→下一动作。无仓库时跳过git核对并写原因；工具状态不明不当成成功。达到当前下一步的必要信息就停止准备，不不断加访谈/插件/代理。现场、模型/工具、授权或任务方向变了才重校准受影响项。
